请以技术评审身份评价一个自用A股工具的数据层方案。现状：Windows本地，腾讯实时/日K+BaoStock双源校验已跑通，指标/选股已有；缺口是全市场5000+股票池、财务/估值、资金流/龙虎榜/公告、分钟/逐笔。当前网络在海外：东财push2/push2his被拒，但腾讯、BaoStock、新浪、巨潮、同花顺K线、交易所官方清单、通达信TCP可用。计划保留现有UI，引入CNEquity（Apache-2.0，本地Parquet数据湖，86个数据集）作为底座，先全市场3年初始化，选股改读本地，财务/公告加面板。请回答：1）这个方案是否可行；2）最大风险是什么；3）给3条具体改进建议；4）CNEquity、astock-data-toolkit、stockdb你会怎么选？不要泛泛而谈。

思考了 56秒

结论先说：方案可行，且与你的缺口高度匹配；在海外网络 + Windows 自用场景下，CNEquity 是三者中最合适的底座。 但有明确的工程边界和风险，不能当“开箱即用全覆盖”。

1）方案是否可行

可行。 理由具体到你的现状：

覆盖对口：CNEquity 的 L0–L4（证券主数据/日历/交易状态、日线+复权因子+退市、公司行为/公告索引、财报/估值/股本、北向/融资融券/龙虎榜/资金流）正好填你列的缺口；分钟/分笔是可选扩展（默认关，按需开）。86 个数据集（78 curated + 8 derived），本地 Parquet，内置增量、水位、续跑、行级溯源、严格 PIT（按公告日）、保留退市股——这些是你现有“腾讯+BaoStock 双源校验 + 指标/选股”升级到全市场研究底座真正缺的部分。
源与海外网络兼容：主行情路径走通达信 TCP（你已确认可用），备源含 BaoStock、新浪、巨潮、交易所公开清单；东财 HTTP 用于资金/估值/部分结构，但不是日线主路径。东财 push2 被拒对你影响有限。Windows 原生支持（文档明确 macOS/Linux/Windows，Python ≥3.11）。
落地路径匹配计划：cne init 默认就是沪深京全市场近 3 年主干（支持中断续传）；之后 cne run daily 日更；from cnequity.query import load 直接读本地，选股改读本地、财务/公告加面板完全可做，且保留现有 UI（数据层解耦）。
许可与自用：Apache-2.0 代码；数据受上游条款约束（不随仓库再分发），自用本地湖没问题。

边界（必须认清）：

分钟线历史深度受源端限制（约 95 个交易日 1 分钟等），分笔是 Level-1 3 秒快照聚合（时间戳到分钟，非交易所逐笔），不是完整 Level-2。
全市场 3 年首次 init 需要数小时级（网络+磁盘），磁盘占用按日线+财务+资金估计数十 GB 起（分钟/分笔再大幅上升）。
0.x 阶段，接口/配置会演进（有 cne config upgrade / migrate）。
2）最大风险

海外网络下“主源可达性 + 部分数据集单源脆弱性”叠加的长期稳定性风险，而不是“能不能跑通一次”。

具体拆解：

日线/证券列表主源是通达信 TCP。你现在能连，但公共行情服务器列表、限速、IP 地理策略随时可变；海外延迟/丢包会放大批次失败率。CNEquity 有备源路由和续跑，但东财相关接口（资金流、部分估值/结构）在海外本就容易被拒或限速——你已踩过 push2。
资金流/龙虎榜/部分公告索引对东财/巨潮依赖更高。源端改版、字段变更、限速升级时，扩展数据集可能长期缺口，而核心日线相对更稳。
次要但真实：全市场 3 年 init 中途网络抖动 → 大量 partial 批次需要人工盯 cne check 和重试；Windows 磁盘/杀软对大量小 Parquet 写入的性能干扰；PIT/退市证据不完整时选股回测会 silently 偏差（虽有审计，但需你主动用）。

如果只做“能跑通一次 3 年日线”，风险可控；如果要日更 + 资金/公告面板长期可用，最大风险就是源端漂移 + 海外可达性，没有 SLA。

3）三条具体改进建议

先跑 demo + 小范围验证，再全市场 init；强制做源可达性与双源对照
cne init --profile demo（5 只近 30 日）→ 确认 TDX/BaoStock/新浪路径在你机器上的延迟与失败率。然后对 50–100 只（含你现有池 + 几只退市/ST）跑正式 init 的子集，用你已有腾讯+BaoStock 日线做字段级 diff（价格容差、量额单位、复权因子）。全市场 init 前在配置里调低并发、显式优先 TDX，并准备好 cne check 的缺口报告脚本。不要直接 cne init 全量赌一次成功。

数据层与现有选股/UI 用“只读契约 + 版本水位”解耦，而不是直接换源
选股引擎改读 load("daily_bars", profile=..., symbols=...) 或 DuckDB/Polars 直接扫 Parquet；保留你现有的双源校验逻辑作为“日更后的旁路审计”（对比 CNEquity 新 revision 与腾讯/BaoStock）。财务/公告面板只读已发布 revision，并在 UI 上暴露 data_version / fetched_at / coverage gap。这样即使某天东财相关数据集失败，日线选股不中断。

分钟/逐笔与资金流分阶段、按需开启，并设磁盘与历史窗口预算
默认只开 core（日线+财务+估值+龙虎榜等）；分钟/分笔用配置显式 enable，并限制回填窗口（例如最近 60–90 个交易日）和股票池（只对自己的关注池）。资金流/公告用事件组或独立调度，避免和日线抢带宽。提前规划磁盘（日线 3 年全市场通常可接受；分钟全市场会到数百 GB 级）和备份策略（只备份已发布 revision）。

4）CNEquity / astock-data-toolkit / stockdb 怎么选

在你描述的场景下（Windows 本地、海外、已有腾讯+BaoStock、要全市场 3 年 + 财务/估值/资金/公告、保留 UI、自用研究/选股），选 CNEquity。

对比要点（针对你的需求，不是泛泛星数）：

维度	CNEquity	astock-data-toolkit（tiantianlaolao）	stockdb（free-stockdb 一类）
定位	本地 Parquet 数据湖 + 增量编排 + PIT/退市/溯源	一站式下载+增量周更（Parquet+SQLite），覆盖行情/估值/财务/分红/公告/增减持	本地高性能行情引擎（日/分钟/tick），偏查询与指标计算
全市场 3 年 + 财务/资金/公告	原生支持，分层数据集，init 即近 3 年主干	有本地化意图，但项目体量小、文档/维护可见度低，是否同等深度的 PIT/退市/资金流不清晰	强在行情与分钟/tick 批量查询；财务/龙虎榜/公告/完整资金面不是主战场
海外源兼容	主路径 TDX TCP + BaoStock/新浪/巨潮，东财非日线主路径	依赖具体实现（常见东财/同类 HTTP 较多）	依赖其 sync 源；公开信息更偏“下好包再查”
工程成熟度（自用）	有 CLI（init/run/check/serve）、续跑、审计、MCP、Windows 支持、活跃 changelog	Stars/可见度低，更像个人工具箱	查询性能强，但数据获取与质量治理（PIT、退市证据、多源仲裁）弱于 CNEquity
与你现有栈	选股改读本地、面板加财务/公告最顺；可继续用腾讯做实时旁路	可能省事下载，但治理与日更编排要你自己补	若核心只要极速分钟/日线回测可考虑，但缺口填不满

不选另外两个的原因（针对你）：

astock-data-toolkit：定位接近“下载工具箱”，但公开信息少、社区与文档厚度远不及 CNEquity；你需要的是可审计、可续跑、带 PIT 的湖，而不是再包一层下载脚本。
stockdb（free-stockdb）：分钟/tick 与批量指标查询很强，适合已经有干净行情包的人；你缺的是财务/估值/资金/公告/退市的一体化治理，它补不了，反而会让你维护两套底座。

实操建议：以 CNEquity 为唯一历史/基本面/资金底座；实时行情继续用你已跑通的腾讯；分钟/分笔等确认磁盘与源稳定性后再开。先 demo → 小池对照 → 全市场 3 年 init → 选股切本地 → 再加面板。这样风险可控，收益最大。

结论：部分有用。 对你们「行情 + 选股」工作台，值得吸收的是过滤器思路和纪律机制，不值得整套照搬成主策略。AliceMarket 在数据/投研能力上更对口，但不是免费无限制。

1）迁移到 A 股是否成立？失真点

逻辑骨架（趋势过滤 + 量能确认 + K 线强度 + 信号上限）可以迁，但原版是 美股/加密日内 scalp（1/3/5m 执行 + 15m HTF），直接套到 A 股日线/60m/15m 会失真。

因素	影响
T+1	当日买入不能卖；“日内 scalp 多次进出”在 A 股变成隔夜持仓风险。卖出信号只能用于已有仓位，不能当日平掉新开多。
涨跌停	接近涨停时量价失真、封板后无法买入；跌停无法卖出。信号在 ±7%～±9% 附近应降权或作废。
集合竞价	9:15–9:25 无连续成交，VWAP/成交量从 9:30 连续竞价起算更合理；若从 9:25 撮合价起算会混入竞价噪声。
成交量结构	A 股早盘/尾盘量尖峰、午休断档；“过去 20 根均量×1.2”在 15m/60m 上可做，但早盘前 2–3 根、尾盘最后 2 根易假突破。日线上“20 日均量”更稳，但会丢掉日内节奏。
VWAP 语义	原版是 session VWAP（当日重置）。日线无“当日 session”概念，应改成 当日分时 VWAP（15m/60m）或 锚定开盘的滚动 VWAP；全市场日线用“近 N 日成交额加权均价”才有可比性。
做空	A 股融券受限，卖出信号主要作空仓/减仓，不能对称做空。

适用结论：更适合 15m/60m 波段过滤 + 选股后的入场纪律，不适合当日线主选股公式，也不适合当高频 scalp 引擎。

2）应吸收什么：P0 / P1 / P2
优先级	内容	说明
P0	量能门 + K 线实体强度 + 每日信号上限	直接可做选股后的 执行过滤器；降低震荡市假突破与过度交易，和你们现有双源校验、选股面板兼容。
P1	单票状态面板（VWAP 位置 / 量比 / 实体比 / 剩余次数）	挂在已有 UI 上，给人工确认用，不自动下单。
P1	高周期趋势方向（60m 或日线 Supertrend/等价趋势）作方向门	只做多头过滤（或只做空头减仓），不做双向 scalp。
P2	完整 Pine 复刻、1/3/5m 多周期共振、收盘确认警报	周期与 T+1 不匹配，投入产出低；警报可后做。
不做	当主选股模型、全市场扫描唯一信号源	原版无基本面/资金/公告，和你们缺口（财务、龙虎榜、公告）不重叠。

文本
# 伪代码：单票、单交易日
session_start = 09:30
max_signals = 3
vol_mult = 1.2
body_min = 0.50
htf = "60m" or "1d"   # Supertrend 方向

on each bar close (tf in {15m, 60m}):
  if time < session_start or is_limit_up/down: skip

  vwap = cum(typical_price * volume) / cum(volume)  # 当日重置
  st_dir = supertrend_direction(htf, atr=10, mult=3)

  vol_ok = volume > vol_mult * sma(volume, 20)
  range = high - low
  body = abs(close - open)
  body_ok = (range > 0) and (body / range >= body_min)

  long_ready  = close > vwap and st_dir == +1 and vol_ok and body_ok
  # short_ready 仅用于已有仓减仓，且 T+1 允许卖

  if long_ready and signals_today < max_signals and not same_direction_as_last:
      emit LONG
      signals_today += 1
  if signals_today >= max_signals: lock until next session

选股侧可降级为硬过滤：close > VWAP_session 且 vol_ratio >= 1.2 且 body_ratio >= 0.5 且 日线/60m 趋势向上，再进你们现有排序。

4）过拟合与样本外：最小验收

防过拟合

参数网格只动 3 个：vol_mult ∈ {1.1,1.2,1.5}，body_min ∈ {0.4,0.5,0.6}，max_signals ∈ {2,3,4}；Supertrend 固定 10/3。
时间切分：训练 2022–2024，样本外 2025–2026；再按牛/震荡/熊分段。
标的：沪深 300 成分 + 中证 1000 各抽 50 只，或你们真实股票池；剔除 ST、上市不足 60 日。
成本：佣金+印花税+滑点（建议单边 0.1%～0.15%）；涨跌停日信号作废或延迟。
只做多 + T+1：信号日收盘买、次日及以后卖；禁止当日买卖。

最小验收指标（不过线就不进生产）

样本外：相对买入持有或你们现有选股基线，收益不显著变差，且 最大回撤不恶化超过 20% 相对幅度。
交易次数：信号密度相对“无过滤”下降 ≥40%，但年化有效交易日仍 ≥ 基线的 50%（避免滤成零信号）。
胜率不是目标；看 盈亏比 × 频率 与 单笔平均滑点后净期望 > 0。
稳健性：三个参数组合里至少 2 个方向一致，否则判定过拟合。
5）AliceMarket（万得 34 Skills/MCP）是否更值得接入？能否免费自用？

更值得优先评估接入，但不是“免费无限自用”。
